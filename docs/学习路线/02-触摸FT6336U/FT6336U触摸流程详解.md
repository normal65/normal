# FT6336U 触摸流程详解（代码 + 手册对照）

> 对应硬件：**FT6336U 电容触摸控制器**  
> 对应手册：`docs/datasheets/ft6336u/D-FT6336U-DataSheet-V1.0.pdf`（12 页）  
> 对应代码：
> - `main/bsp/driver/ft6336u/ft6336u.cc/.hpp`
> - `main/bsp/driver/ft6336u/touch_gesture.cc/.hpp`
> - `main/app/ebook/input/input_router.cc/.hpp`
> - `main/app/ebook/input/gesture_tuner.cc/.hpp`

---

## 0. 一句话理解触摸链路

```text
手指按下
→ FT6336U 拉低 INT
→ ESP32 GPIO 中断
→ 中断只给信号量发通知
→ 输入任务被唤醒
→ 通过 I2C 读坐标
→ 手势状态机判断 Tap / Swipe / LongPress
→ 通过 UiBus 把事件交给 UI 线程
→ 当前页面处理点击
```

记住两句话：

1. **中断只敲门，不干活。**
2. **输入任务只发消息，不直接改界面。**

## 1. 先看硬件：引脚怎么接

### 1.1 FT6336U 手册里的引脚

FT6336U 手册第 10–11 页 Table 4-1：

| 手册引脚 | 名称 | 作用 |
|---|---|---|
| 41 | RSTN | 外部复位，低电平有效 |
| 42 | IOVCC | IO 电源 |
| 43 | SCL | I2C 时钟 |
| 44 | SDA | I2C 数据 |
| 45 | INT | 中断输出，通知主机“有触摸数据” |
| 39 | VDDA | 模拟电源 |
| 40 | VDDD | 数字电源 |
| 38 | VDD5 | 内部电荷泵高压 |
| 46 | VREF | 内部参考电压，需要 1µF 电容 |

### 1.2 本板实际接法（面板/芯片引脚 → ESP32 GPIO）

本板原理图和 `main/bsp/config/config.hpp`：

| FT6336U 信号 | ESP32-S3 GPIO | 方向 | 说明 |
|---|---|---|---|
| SDA | GPIO2 | 双向 | I2C 数据 |
| SCL | GPIO1 | ESP32 → FT6336U | I2C 时钟 |
| RSTN | GPIO18 | ESP32 → FT6336U | 复位，低有效 |
| INT | GPIO5 | FT6336U → ESP32 | 中断，有触摸时拉低 |

> 注意：FT6336U 手册给的是芯片引脚号（41/43/44/45），不是 ESP32 GPIO。  
> GPIO 编号来自本板原理图和 `config.hpp`。

### 1.3 手册里的复位时序

FT6336U 手册第 8–9 页 3.5 Power On/Reset/Wake Sequence：

| 参数 | 含义 | 最小值 |
|---|---|---|
| Trst | 复位低电平时间 | **5ms** |
| Trsi | 复位后到开始上报点的时间 | **300ms** |
| Tpon | 上电后到开始上报点的时间 | 300ms |
| Tprt | 上电后低电平时间 | 1ms |
| Tris | 电源上升时间 | 最大 3ms |

代码里：

```cpp
gpio_set_level(FT6336_RST, 0);
delay_ms(10);    // 手册要求 >= 5ms
gpio_set_level(FT6336_RST, 1);
delay_ms(300);   // 手册要求 >= 300ms
```

**这是代码和手册完全对得上的地方。**

## 2. 初始化流程

### 2.1 代码位置

`main/bsp/driver/ft6336u/ft6336u.cc`，`Ft6336u::init()`

### 2.2 初始化顺序

```text
1. 配置 INT 为输入 + 上拉
2. 硬件复位：RST 低 10ms，高 300ms
3. 在 I2C 总线上挂载设备（地址 0x38）
4. 读芯片 ID（probe）
5. 写基础寄存器
6. 打开中断
```

### 2.3 I2C 地址

代码：

```cpp
constexpr uint8_t kI2cAddr = 0x38;
```

FT6336U 使用 7 位 I2C 地址 **0x38**。

### 2.4 INT 引脚

```cpp
gpio_config_t int_cfg = {};
int_cfg.pin_bit_mask = (1ULL << config::FT6336_INT);
int_cfg.mode = GPIO_MODE_INPUT;
int_cfg.pull_up_en = GPIO_PULLUP_ENABLE;
int_cfg.intr_type = GPIO_INTR_DISABLE;
gpio_config(&int_cfg);
```

为什么先 `GPIO_INTR_DISABLE`？

因为这时还没准备好中断处理函数和信号量。等 `enable_interrupt()` 时再打开，避免一上来就进中断。

### 2.5 硬件复位

```cpp
void Ft6336u::hw_reset()
{
    gpio_set_level(config::FT6336_RST, 0);
    delay_ms(10);
    gpio_set_level(config::FT6336_RST, 1);
    delay_ms(300);
}
```

手册对应：

- Trst ≥ 5ms → 代码 10ms
- Trsi ≥ 300ms → 代码 300ms

### 2.6 探测芯片

`probe_chip()` 会读几个 ID 寄存器：

- `REG_CIPHER_HIGH`（0xA3）
- `REG_CIPHER_LOW`（0xA0）
- `REG_FOCALTECH_ID`（0xA8）

期望值：

```cpp
kCipherHighExpected = 0x64;
kFocalTechId = 0x11;
cipher_lo == 0x01 || cipher_lo == 0x02;
```

如果读不到典型 ID，但能读触摸状态寄存器，也认为芯片可用（兼容部分批次）。

### 2.7 写基础寄存器

`setup_base_regs()`：

| 寄存器 | 值 | 作用 |
|---|---|---|
| `REG_MODE` 0x00 | 0x00 | 正常工作模式 |
| `REG_THGROUP` 0x80 | 30 | 触摸阈值 |
| `REG_CTRL` 0x86 | 0x00 | 控制寄存器 |
| `REG_PERIODACTIVE` 0x88 | 0x08 | 活跃模式上报周期 |
| `REG_REPORT_INT_MODE` 0xA4 | 0x01 | 中断上报模式 |
| `REG_WORK_STATE` 0xBC | 0x01 | 进入工作状态 |

## 3. 中断是怎么工作的

### 3.1 中断服务函数

`ft6336u.cc` 顶部的匿名命名空间：

```cpp
void IRAM_ATTR int_isr_handler(void*)
{
    BaseType_t wake = pdFALSE;
    if (g_int_sem != nullptr)
        xSemaphoreGiveFromISR(g_int_sem, &wake);
    if (wake == pdTRUE)
        portYIELD_FROM_ISR();
}
```

### 3.2 人话解释

FT6336U 检测到触摸时，会把 INT 引脚拉低。  
ESP32 的 GPIO 中断被触发，进入 `int_isr_handler()`。

这个函数只做一件事：

```text
给信号量 g_int_sem 发一个通知
```

它**不读 I2C、不打印日志、不处理坐标**。

### 3.3 为什么中断里不读 I2C

I2C 传输需要：

- 等总线
- 等 ACK
- 可能失败重试
- 可能耗时几百微秒到几毫秒

在中断里等这么久会拖慢整个系统。  
所以中断只“敲门”，真正的读取交给任务。

### 3.4 打开中断

`Ft6336u::enable_interrupt()`：

1. 创建二进制信号量 `g_int_sem`
2. 安装 GPIO 中断服务 `gpio_install_isr_service()`
3. 把 `int_isr_handler` 挂到 INT 引脚
4. 设置触发方式为 `GPIO_INTR_ANYEDGE`（按下和抬起都通知）

### 3.5 任务等待中断

`Ft6336u::wait_interrupt()`：

```cpp
xSemaphoreTake(g_int_sem, 0);  // 先清掉旧标记
return xSemaphoreTake(g_int_sem, pdMS_TO_TICKS(timeout_ms)) == pdTRUE;
```

先 `take(0)` 清一次，再正式 `take(timeout)`，避免被上一次的旧通知立刻唤醒。

## 4. 输入任务怎么读触摸

### 4.1 任务主体

`InputRouter::task_main()`（`input_router.cc`）：

```cpp
while (running_)
{
    if (!dev_->wait_interrupt(kIdlePollMs))
    {
        gesture_.poll();
        gesture_.tick();
        drain_events();
        process_release();
        continue;
    }

    gesture_.poll();
    drain_events();
    ...
}
```

两种状态：

- **没触摸**：等中断，最多等 20ms；超时也 `poll()` 一次，防止漏掉。
- **有触摸**：连续读、连续判断，直到手指离开。

### 4.2 读一次触摸

`TouchGesture::poll()`：

```cpp
TouchSample sample = {};
if (!touch_->read(sample))
    return false;
return process_sample(sample);
```

`Ft6336u::read()`：

1. 读 `REG_TD_STATUS`（0x02）
2. 读 13 字节触摸数据
3. 再读一次，如果两次不一致，以第二次为准
4. 解析触点数
5. 每个触点解析 x / y
6. 对坐标做 swap / mirror / 裁剪

### 4.3 为什么要读两次

因为触摸芯片在更新的瞬间，可能读到“半新半旧”的数据。  
读两次能大幅降低错误坐标的概率。

### 4.4 坐标解析

每个触点 6 字节：

```text
byte0: event + x 高 4 位
byte1: x 低 8 位
byte2: y 高 4 位
byte3: y 低 8 位
```

代码：

```cpp
pt.x = ((buf[0] & 0x0F) << 8) | buf[1];
pt.y = ((buf[2] & 0x0F) << 8) | buf[3];
```

### 4.5 坐标校正

`map_coord()`：

- `swap_xy`：交换 X/Y
- `mirror_x` / `mirror_y`：镜像
- 最后裁剪到 `0 ~ WIDTH-1` / `0 ~ HEIGHT-1`

注意：

> 坐标翻转只应该在一个地方做。  
> 如果驱动做了一次，手势层又做一次，就会翻回来。

## 5. 手势状态机

### 5.1 三个状态

`TouchGesture` 内部：

```text
Idle（没手指）
  │ 检测到触点
  ▼
Pressed（按着，还没判定）
  │ 按住够久 + 位置稳定
  ▼
LongPressSent（已发长按，等抬手）
  │ 抬手
  ▼
Idle
```

### 5.2 点击 / 滑动 / 长按怎么区分

`finish_contact()` 在抬手时统一结算：

```text
1. 位移够大 + 时间够短  → SwipeLeft/Right/Up/Down
2. 位移小 + 时间短      → Tap
3. 都不是              → 什么都不发
```

判断参数在 `GestureConfig`：

| 参数 | 默认值 | 含义 |
|---|---|---|
| `tap_max_move_px` | 15 | 点击允许的最大位移 |
| `tap_max_duration_ms` | 250 | 点击允许的最长时间 |
| `long_press_ms` | 700 | 长按触发时间 |
| `long_press_stable_frames` | 4 | 长按需要位置稳定的帧数 |
| `swipe_min_distance_px` | 28 | 滑动最小距离 |
| `swipe_axis_lock_px` | 16 | 主方向领先阈值 |
| `swipe_max_duration_ms` | 800 | 滑动最长时间 |
| `gesture_cooldown_ms` | 150 | 两次手势之间的冷却 |

### 5.3 三种档位

`gesture_tuner.cc`：

| 档位 | 用途 | 特殊设置 |
|---|---|---|
| `Normal` | 日常点击/滑动 | 默认参数 |
| `Keyboard` | 软键盘 | 冷却缩短到 30ms |
| `Drawing` | 画板 | 发 Press/Move/Release，禁用滑动和长按 |

## 6. 事件怎么到 UI

### 6.1 投递到 UiBus

`InputRouter::drain_events()`：

```cpp
while (gesture_.has_event())
{
    const Event ev = gesture_.take_event();
    (void)ui::UiBus::get_instance().post_input(ev);
}
```

### 6.2 UI 线程取事件

`UiLoop::run()`：

```cpp
if (!bus.recv(ev, portMAX_DELAY))
    continue;
handle_event(ev);
```

`UiLoop::handle_event()` 根据事件类型分流，触摸事件进入 `dispatch_input()`。

### 6.3 为什么不能直接调用页面

因为输入任务和 UI 线程是两个并行任务。  
直接调用页面会同时修改 UI 状态，产生数据竞争。

正确做法：

> 输入任务只发消息，UI 线程负责处理消息。

## 8. 常见坑

### 8.1 触摸完全没反应

按顺序查：

1. INT 有没有上拉、有没有注册中断
2. I2C 地址是不是 0x38
3. RST 有没有拉低再拉高
4. 复位后有没有等 300ms
5. `probe_chip()` 能不能读到 ID
6. `poll()` 能不能读到 `sample.count > 0`
7. 事件有没有进 UiBus

### 8.2 坐标方向不对

- 只在一个地方做 swap/mirror
- 先确认屏幕旋转方向
- 再确认触摸排线方向

### 8.3 点击不灵 / 滑动太敏感

调 `GestureConfig`：

- 点击不灵：增大 `tap_max_move_px` 或 `tap_max_duration_ms`
- 滑动太敏感：增大 `swipe_min_distance_px` 或 `swipe_axis_lock_px`
- 长按误触：增大 `long_press_ms` 或 `long_press_stable_frames`

### 8.4 中断一直触发

- INT 引脚可能没有上拉
- 触摸芯片可能一直在上报
- 检查 `REG_PERIODACTIVE` / `REG_REPORT_INT_MODE`

**INT 中断只发信号量；输入任务通过 I2C 读坐标；手势状态机把坐标变成 Tap/Swipe/LongPress；事件通过 UiBus 交给 UI 线程。**
