# 按键与拨码流程详解（代码 + 硬件对照）

> 对应硬件：**三档 ADC 拨码开关（UP / MID / DOWN）**
> 对应代码：
> - `main/bsp/driver/button/button.cc/.hpp`（ADC 驱动）
> - `main/app/ebook/input/physical_input.cc/.hpp`（去抖 + 边沿检测）
> - `main/app/ebook/input/physical_types.hpp`（事件类型）
> - `main/app/ebook/input/input_dispatch.cc`（按键语义分发）
>
> 这个模块没有独立芯片手册。硬件定义在本板原理图和 `main/bsp/config/config.hpp`；ADC 是 ESP32-S3 内置外设。

---

## 0. 一句话理解按键链路

```text
拨码/按键改变分压
→ GPIO15 电压变化
→ ADC 采样
→ 按阈值分类成 UP / MID / DOWN / NONE
→ 连续 3 次一致才认
→ 产生 Press / Release
→ UiBus 队列
→ UI 线程
→ dispatch_physical()
→ 当前页面或全局功能
```

---

## 1. 为什么一个引脚能表示三个按键

板子上不是三个独立 GPIO，而是：

```text
3.3V
  │
  ├─ 电阻
  │
GPIO15（ADC 输入）
  │
  ├─ 按键 UP   → 分压到约 551mV
  ├─ 按键 MID  → 分压到约 1102mV
  ├─ 按键 DOWN → 分压到约 1651mV
  └─ 未按下    → 被拉高到约 3300mV
```

不同按键把 GPIO15 拉到不同的电压，ESP32 用 ADC 读这个电压，就能区分按了哪一个。

### 1.1 实测电压

`main/bsp/config/config.hpp` 里写的是实测值：

| 状态 | 电压 |
|---|---|
| UP | 约 551mV |
| MID | 约 1102mV |
| DOWN | 约 1651mV |
| 未按下 | 约 3300mV |

### 1.2 阈值

代码不直接比较 551/1102/1651，而是取中间值做阈值：

| 阈值 | 值 | 含义 |
|---|---|---|
| `DIP_SWITCH_THRESHOLD_UP_MID_MV` | 830 | UP 和 MID 的分界 |
| `DIP_SWITCH_THRESHOLD_MID_DOWN_MV` | 1380 | MID 和 DOWN 的分界 |
| `DIP_SWITCH_THRESHOLD_RELEASED_MV` | 2100 | DOWN 和“未按下”的分界 |

分类逻辑：

```text
mv >= 2100  → NONE（未按下）
mv <  830   → UP
mv <  1380  → MID
否则        → DOWN
```

对应代码 `classify_position()`。

## 2. ADC 初始化

### 2.1 代码位置

`main/bsp/driver/button/button.cc`，`DipSwitch::init()`

### 2.2 初始化顺序

```text
1. 把 GPIO15 映射到 ADC 单元/通道
2. 创建 ADC oneshot 单元
3. 配置通道：12dB 衰减、12 位分辨率
4. 创建校准句柄（曲线拟合或线拟合）
5. 读一次电压和档位，打印日志
```

### 2.3 ADC 参数

- **12dB 衰减**：让 ADC 能测到约 3.3V 的电压
- **12 位分辨率**：原始值 0~4095

### 2.4 校准

代码优先使用 ESP-IDF 的校准方案：

- 曲线拟合 `adc_cali_create_scheme_curve_fitting()`
- 或线拟合 `adc_cali_create_scheme_line_fitting()`

如果校准不可用，会退化成：

```cpp
voltage_mv = raw * 3100 / 4095;
```

这时电压读数可能不够准，但按键分档通常仍然可用。

## 3. 读电压

### 3.1 代码位置

`DipSwitch::read_voltage_mv()`

### 3.2 采样方式

不是只读一次，而是：

```text
连续采样 8 次
→ 去掉失败样本
→ 求平均
→ raw 转 mV
```

为什么要多次采样：

- ADC 有噪声
- 电源有波动
- 按键接触有抖动

平均之后电压更稳。

## 4. 分类档位

### 4.1 代码

```cpp
DipId classify_position(uint32_t mv, const Config& cfg)
{
    if (mv >= cfg.threshold_released_mv)
        return DipId::NONE;
    if (mv < cfg.threshold_up_mid_mv)
        return DipId::UP;
    if (mv < cfg.threshold_mid_down_mv)
        return DipId::MID;
    return DipId::DOWN;
}
```

### 4.2 为什么用区间而不是精确值

因为：

- 电阻有误差
- 电源有波动
- ADC 有噪声
- 温度会改变分压

如果写 `if (mv == 551)`，几乎永远不成立。  
用区间判断才可靠。

## 5. 去抖

### 5.1 代码位置

`main/app/ebook/input/physical_input.cc`，`PhysicalInput::poll_once()`

### 5.2 去抖规则

```text
每 25ms 读一次
→ 如果和当前稳定档位相同：清空 pending
→ 如果和 pending 相同：计数 +1
→ 如果和 pending 不同：重新开始计数
→ 连续 3 次一致：才更新 stable_
```

`kDebounceSamples = 3`，`kPollMs = 25`，所以大约需要 **75ms** 才能确认一次变化。

### 5.3 为什么需要去抖

机械按键和拨码在切换瞬间会快速通断多次，ADC 会读到一串跳变值。  
如果不去抖，一次按键可能产生多次 Press/Release。

## 6. 边沿检测与事件

### 6.1 什么情况发 Press

当稳定档位从 `NONE` 变成 `UP/MID/DOWN`：

```cpp
if (stable_ != DipId::NONE)
{
    post_physical(map_key(stable_), PhysicalAction::Press);
}
```

### 6.2 什么情况发 Release

当稳定档位从 `UP/MID/DOWN` 变回 `NONE`：

```cpp
if (prev != DipId::NONE)
{
    post_physical(map_key(prev), PhysicalAction::Release);
}
```

### 6.3 冷却时间

`kCooldownMs = 180`：

```text
两次事件之间至少间隔 180ms
```

防止一次拨动产生连发。

### 6.4 事件类型

```cpp
enum class PhysicalKey : uint8_t { Up, Mid, Down };
enum class PhysicalAction : uint8_t { Press, Release };
```

---

## 7. 事件怎么到 UI

### 7.1 投递到 UiBus

```cpp
void post_physical(PhysicalKey key, PhysicalAction action)
{
    (void)ui::UiBus::get_instance().post_physical(key, action);
}
```

`UiBus::post_physical()` 把事件包装成 `UiEventKind::PhysicalInput`，放进队列。

### 7.2 UI 线程处理

`UiLoop::handle_event()`：

```cpp
case UiEventKind::PhysicalInput:
    dispatch_physical(pe);
    break;
```

### 7.3 语义分发

`input_dispatch.cc` 把物理按键翻译成“语义动作”：

```text
Up / Mid / Down + Press / Release
→ PageNext / PagePrev / Back / Home / ...
→ Router 或当前 App
```

这样页面不需要知道“是哪个 GPIO”，只需要知道“用户想干什么”。

## 8. 完整链路

```text
拨码改变
→ GPIO15 电压变化
→ DipSwitch::read_voltage_mv() 采样 8 次求平均
→ classify_position() 分类
→ PhysicalInput::poll_once() 连续 3 次确认
→ post_physical()
→ UiBus::post_physical()
→ UiLoop::handle_event()
→ dispatch_physical()
→ KeyBindings / dispatch_semantic()
→ 当前页面或全局功能
```

## 9. 常见坑

### 9.1 按键识别成另一个档位

- 阈值和实际分压不匹配
- 电阻误差大
- ADC 校准不可用
- 电源电压不是 3.3V

解决：

1. 打印 `read_voltage_mv()`
2. 记录三档实际电压
3. 重新计算中间阈值

### 9.2 一次按键触发多次

- 去抖次数太少
- 冷却时间太短
- 拨码接触不良

解决：

- 增大 `kDebounceSamples`
- 增大 `kCooldownMs`
- 检查焊接和拨码开关

### 9.3 一直识别为 NONE

- GPIO15 没接对
- ADC 通道映射失败
- 分压电阻没焊
- 拨码开关没接 GND

### 9.4 一直识别为 DOWN

- 电压低于 1380mV
- 可能短路到地
- 检查分压网络

## 11. 一句话总结

**一个 ADC 引脚 + 分压网络区分三档；ADC 多次采样求平均；软件连续 3 次一致才确认；确认后发 Press/Release，通过 UiBus 交给 UI 线程处理。**
