## 2. 第 0 步：硬件上电（代码不控制）

### 这一步在做什么

给屏幕供电：

- `VCI`：芯片主电源
- `VDDIO`：接口逻辑电源，接 VCI
- `VDD`：核心逻辑电源，由 VCI 内部稳压，**VDD 与 VSS 之间要接电容**
- `VSS / VSSA / VSSBG / VSSGS`：地

### SSD1680 手册依据

**第 7 页 Table 5-1：**

| 引脚 | 原文 | 中文 |
|---|---|---|
| VCI | `Power input pin for the chip.` | 芯片主电源输入 |
| VDDIO | `Power input pin for the Interface. Connect to VCI.` | 接口逻辑电源，接 VCI |
| VDD | `Core logic power pin. A capacitor should be connected between VDD and VSS.` | 核心逻辑电源，VDD 与 VSS 之间必须接电容 |
| VSS | `Ground (Digital).` | 数字地 |

### 面板手册依据

**第 8 页 Note 5-3：**

> `This pin (RES#) is reset signal input. The Reset is active low.`

**第 32 页 14.1：**

```text
1. Power On
   • Supply VCI
   • Wait 10ms
```

### 为什么先讲这个

因为后面所有命令都建立在“电已经稳定”这个前提上。
如果 VCI 还没稳，就发复位或命令，控制器可能不响应。

## 3. 第 1 步：配置 GPIO

### 代码位置

`main/bsp/driver/gdey027t91/gdey027t91.cc:119`，`Gdey027t91::init()`

### 代码

```cpp
gpio_config_t out_cfg = {};
out_cfg.pin_bit_mask = (1ULL << config::GDEY027T91_DC) |
                       (1ULL << config::GDEY027T91_RST) |
                       (1ULL << config::GDEY027T91_CS);
out_cfg.mode = GPIO_MODE_OUTPUT;
gpio_config(&out_cfg);

gpio_config_t in_cfg = {};
in_cfg.pin_bit_mask = (1ULL << config::GDEY027T91_BUSY);
in_cfg.mode = GPIO_MODE_INPUT;
gpio_config(&in_cfg);

gpio_set_level(config::GDEY027T91_CS, 1);
```

### 人话解释

- `DC`、`RST`、`CS` 是 ESP32 输出给屏幕的控制信号
- `BUSY` 是屏幕输出给 ESP32 的状态信号
- `CS` 先拉高，表示“现在还没选中屏幕”

### 引脚对应（重点，别把两层混了）

这里有三层名字，必须分开看：

1. **面板 FPC 引脚号**：面板排线上的第几脚，来自面板手册第 7 页
2. **面板信号名**：面板手册里写的 SCL / SDA / CS# / D/C# / RES# / BUSY
3. **ESP32 GPIO**：本板原理图和 `config.hpp` 里实际接的 GPIO

| 面板 FPC 引脚 | 面板信号 | ESP32-S3 GPIO | ESP32 侧名称 | 方向 |
|---|---|---|---|---|
| 13 | SCL | GPIO46 | SCLK | ESP32 → 屏幕 |
| 14 | SDA | GPIO3 | MOSI | ESP32 → 屏幕 |
| 12 | CS# | GPIO9 | CS | ESP32 → 屏幕 |
| 11 | D/C# | GPIO10 | DC | ESP32 → 屏幕 |
| 10 | RES# | GPIO11 | RST | ESP32 → 屏幕 |
| 9 | BUSY | GPIO12 | BUSY | 屏幕 → ESP32 |

> **为什么面板手册里没有 GPIO3 / GPIO46 / GPIO9 这些编号？**  
> 因为面板手册只描述“屏幕排线第几脚是什么信号”，它不知道你会把这块屏接到哪颗 MCU、哪个 GPIO。  
> GPIO 编号是本板设计者在原理图和 `config.hpp` 里定的，同一块屏接到别的板子，GPIO 编号就会完全不同。

### 同一个信号，两边叫法不同

| 功能 | 面板手册叫法 | ESP32 SPI 叫法 |
|---|---|---|
| 时钟 | SCL | SCLK |
| 数据（主机发） | SDA | MOSI |
| 片选 | CS# | CS |
| 数据/命令 | D/C# | DC |
| 复位 | RES# | RST |
| 忙信号 | BUSY | BUSY |

所以：

- 面板的 **SCL** = ESP32 的 **SCLK** = GPIO46
- 面板的 **SDA** = ESP32 的 **MOSI** = GPIO3
- 面板的 **CS#** = ESP32 的 **CS** = GPIO9
- 面板的 **D/C#** = ESP32 的 **DC** = GPIO10
- 面板的 **RES#** = ESP32 的 **RST** = GPIO11
- 面板的 **BUSY** = ESP32 的 **BUSY** = GPIO12

### 哪些是 SPI，哪些不是

4 线 SPI 真正参与数据传输的是：

```text
SCLK  （时钟，对应面板 SCL，FPC 13 脚，GPIO46）
MOSI  （数据，对应面板 SDA，FPC 14 脚，GPIO3）
CS#   （片选，FPC 12 脚，GPIO9）
D/C#  （命令/数据选择，FPC 11 脚，GPIO10）
```

不是 SPI 的两根：

```text
RES#  （复位，FPC 10 脚，GPIO11）
BUSY  （忙状态，FPC 9 脚，GPIO12）
```

准确说法：

> **这块屏用 4 线 SPI 传命令和数据，另外用 RES# 复位、用 BUSY 查询忙状态。**

### SSD1680 手册依据

**第 8 页 Table 5-2：**

| 引脚 | 原文 | 中文 |
|---|---|---|
| CS# | `Chip select input connecting to the MCU.` | 片选输入，低电平选中 |
| D/C# | `Data/Command control pin connecting to the MCU.` | 数据/命令选择：低=命令，高=数据 |
| RES# | `Reset signal input. Active Low.` | 复位输入，低有效 |
| BUSY | `Busy state output pin. When Busy is High, the operation of the chip should not be interrupted.` | 忙状态输出；高电平=忙，不能打断、不能发命令 |

### 面板手册依据

**第 7 页 5. Input/Output Pin Assignment：**

| 引脚 | 原文 |
|---|---|
| 9 BUSY | `Busy state output pin` |
| 10 RES# | `Reset signal input. Active Low.` |
| 11 D/C# | `Data /Command control pin` |
| 12 CS# | `Chip select input pin` |
| 13 SCL | `Serial Clock pin (SPI)` |
| 14 SDA | `Serial Data pin (SPI)` |

### 常见坑

- `BUSY` 忘配上拉/输入，读不到状态
- `CS` 一开始是低电平，屏幕可能误以为被选中
- `RST` 和 `DC` 接反，表现为完全没反应

## 4. 第 2 步：初始化 SPI

### 代码

```cpp
spi_bus_config_t bus_cfg = {};
bus_cfg.mosi_io_num = config::GDEY027T91_MOSI;
bus_cfg.miso_io_num = -1;
bus_cfg.sclk_io_num = config::GDEY027T91_SCLK;
bus_cfg.quadwp_io_num = -1;
bus_cfg.quadhd_io_num = -1;
bus_cfg.max_transfer_sz = kDmaChunkMax;

spi_bus_initialize(kSpiHost, &bus_cfg, SPI_DMA_CH_AUTO);

spi_device_interface_config_t dev_cfg = {};
dev_cfg.clock_speed_hz = kSpiClockHz;   // 20MHz
dev_cfg.mode = 0;
dev_cfg.spics_io_num = -1;              // CS 自己用 GPIO 控制
dev_cfg.queue_size = 1;
dev_cfg.flags = SPI_DEVICE_HALFDUPLEX;
spi_bus_add_device(kSpiHost, &dev_cfg, &spi->handle);
```

### 人话解释

- 屏幕上只有 MOSI，没有 MISO（只写不读）
- CS 不用硬件 SPI 片选，而是用普通 GPIO 控制
- 20MHz 是手册写模式的上限

### 本项目实际接法（对应面板 FPC 引脚）

| 代码里的字段 | 值 | 对应面板 FPC 引脚 | 面板信号 |
|---|---|---|---|
| `bus_cfg.mosi_io_num` | GPIO3 | 14 | SDA |
| `bus_cfg.sclk_io_num` | GPIO46 | 13 | SCL |
| `dev_cfg.spics_io_num` | -1（用 GPIO9 手动控制） | 12 | CS# |
| D/C# GPIO | GPIO10 | 11 | D/C# |

另外两根不是 SPI 数据线：

- `RST`：GPIO11 → 面板 FPC 10 脚 `RES#`
- `BUSY`：GPIO12 ← 面板 FPC 9 脚 `BUSY`

所以看波形时：

- **SCLK 看 GPIO46，对应面板 13 脚 SCL**
- **MOSI 看 GPIO3，对应面板 14 脚 SDA**
- **CS 看 GPIO9，对应面板 12 脚 CS#**
- **DC 看 GPIO10，对应面板 11 脚 D/C#**
- **RST 看 GPIO11，对应面板 10 脚 RES#**
- **BUSY 看 GPIO12，对应面板 9 脚 BUSY**

### SSD1680 手册依据

**第 10 页 6.1.2：**

> `The 4-wire SPI consists of serial clock SCL, serial data SDA, D/C# and CS#.`

中文：

> 4 线 SPI 由 SCL、SDA、D/C#、CS# 组成。

**第 42 页 Table 12-1（写模式）：**

| 参数 | 最小值 |
|---|---|
| SCL 频率 | 20MHz |
| CS# 拉低到第一个 SCL 上升沿 | 60ns |
| CS# 在最后一个 SCL 下降沿后保持低 | 65ns |
| SDA 建立时间 | 10ns |
| SDA 保持时间 | 40ns |

### 为什么用 20MHz

手册写模式最高 20MHz，代码正好用上限。
如果排线长、信号差，可以降到 10MHz 或 5MHz，先保证稳定。

## 5. 第 3 步：分配 framebuffer

### 代码

```cpp
framebuffer_ = static_cast<uint8_t*>(
    heap_caps_malloc(BUFFER_SIZE, MALLOC_CAP_DMA));
std::memset(framebuffer_, 0xFF, BUFFER_SIZE);
```

### 尺寸怎么来的

文件：`main/bsp/driver/gdey027t91/panel.hpp`

```cpp
static constexpr uint16_t WIDTH  = 176;
static constexpr uint16_t HEIGHT = 264;
static constexpr uint16_t STRIDE = WIDTH / 8;              // 22
static constexpr uint32_t BUFFER_SIZE = STRIDE * HEIGHT;   // 5808
```

### 人话解释

墨水屏是 1-bit：

```text
176 像素 ÷ 8 = 22 字节/行
22 字节/行 × 264 行 = 5808 字节
```

这 5808 字节就是“这一屏要显示什么”。
`0xFF` 表示全白。

### SSD1680 手册依据

**第 5 页：**

> `176 source outputs, 296 gate outputs... support displays with resolution up to 176 x 296.`

**第 13–14 页（RAM / LUT mapping）：**

> 每个像素在 RAM 里占 1 位，8 个像素打包成 1 个字节。

本项目只用 264 行，所以是 176×264。

## 6. 第 4 步：硬件复位 `hw_reset()`

### 代码位置

`gdey027t91.cc:431`

### 代码

```cpp
void Gdey027t91::hw_reset()
{
    gpio_set_level(config::GDEY027T91_RST, 0);
    ::app::sys::task::TaskMgr::delay_ms(Panel::RESET_SETTLE_MS);
    gpio_set_level(config::GDEY027T91_RST, 1);
    ::app::sys::task::TaskMgr::delay_ms(Panel::RESET_SETTLE_MS);
}
```

`Panel::RESET_SETTLE_MS = 10`，所以实际是：

```text
RST = 0 → 等 10ms
RST = 1 → 等 10ms
```

### 这根线是哪一根

| 代码里的名字 | ESP32 GPIO | 面板 FPC 引脚 | 面板信号 | 方向 |
|---|---|---|---|---|
| `GDEY027T91_RST` | GPIO11 | 10 | RES# | ESP32 → 面板 |

注意：`RST` 不是 SPI 信号，它是一根普通的 GPIO 输出，只负责拉低/拉高。

### 人话解释

把控制器的复位脚拉低，让芯片进入复位状态；
再拉高，让芯片从复位中出来；
再等 10ms，让内部电源和振荡器稳定。

### SSD1680 手册依据

**第 8 页 Table 5-2：**

> `RES#: This pin is reset signal input. Active Low.`

中文：

> RES# 是复位输入，低电平有效。

**第 39 页 9.1：**

```text
2. Set Initial Configuration
   • HW Reset
   • SW Reset by Command 0x12
   • Wait 10ms
```

### 面板手册依据

**第 8 页 Note 5-3：**

> `This pin (RES#) is reset signal input. The Reset is active low.`

**第 32 页 14.1：**

```text
1. Power On
   • Supply VCI
   • Wait 10ms
2. Set Initial Configuration
   • HW Reset
   • SW Reset by Command 0x12
   • Wait 10ms
```

### 关于“10ms”的重要结论

我把**面板手册和 SSD1680 手册全文都搜过**：

- 手册明确写了：**复位后 Wait 10ms**
- 手册没有逐字写：**RES# 低电平要保持 10ms**
- 代码里的 10ms 低电平是**工程保守值**
- 面板手册第 12 页有时序图，但它是**图片**，PDF 文字层搜不到具体 tRES

所以：

> **“低 10ms + 高 10ms”不是手册逐字抄的，而是“控制器最小要求 + 工程余量”。**

开机多等 10ms 没有副作用，但能覆盖不同批次屏幕、供电爬升和温度差异。

### 常见坑

- RST 低电平太短，控制器没复位干净
- RST 拉高后没等，立刻发命令，控制器不响应
- 换屏后偶发不启动，可以把 `RESET_SETTLE_MS` 从 10 加到 20 或 50

## 7. 第 5 步：软件复位 `sw_reset()`

### 代码位置

`gdey027t91.cc:478`

### 代码

```cpp
bool Gdey027t91::sw_reset()
{
    cmd(Cmd::kSwReset);      // 0x12
    cs_release();

    if (!wait_busy(Panel::BUSY_TIMEOUT_CMD_MS))
        return false;

    ::app::sys::task::TaskMgr::delay_ms(Panel::RESET_SETTLE_MS);
    return true;
}
```

### 这一步走哪几根线

| 动作 | 走哪根线 | ESP32 GPIO | 面板 FPC 引脚 |
|---|---|---|---|
| 发命令 0x12 | MOSI（SDA） | GPIO3 | 14 SDA |
| 命令字节同步 | SCLK（SCL） | GPIO46 | 13 SCL |
| 选中芯片 | CS# | GPIO9 | 12 CS# |
| 标记这是命令 | D/C# = 0 | GPIO10 | 11 D/C# |
| 等待忙结束 | BUSY | GPIO12 | 9 BUSY |

所以 `sw_reset()` 虽然只写了 `cmd(0x12)`，底层实际是：

```text
CS=低 → DC=低 → SCL 上升沿把 0x12 移进去 → CS=高 → 读 BUSY
```

### BUSY 到底是哪一根

| 代码里的名字 | ESP32 GPIO | 面板 FPC 引脚 | 面板信号 | 方向 |
|---|---|---|---|---|
| `GDEY027T91_BUSY` | GPIO12 | 9 | BUSY | 面板 → ESP32 |

`wait_busy()` 读的就是 GPIO12：

- **高电平 = 面板还在忙**，不能发下一条命令
- **低电平 = 面板空闲**，可以继续

所以代码里：

```cpp
if (!wait_busy(...))
    return false;
```

意思就是“等 GPIO12 变低；如果超时还没变低，就报错”。

### 人话解释

硬件复位是把整块控制器“断电重启”；
软件复位是发命令 0x12，让控制器内部状态机回到初始值。
两个都做，保证控制器一定处于已知状态。

### SSD1680 手册依据

**第 39 页 9.1：**

```text
• SW Reset by Command 0x12
• Wait 10ms
```

**第 7 章 Command Table（第 20–33 页）：**

> 0x12 = SW Reset，软件复位。

### 面板手册依据

**第 32 页 14.1：**

```text
• SW Reset by Command 0x12
• Wait 10ms
```

### 常见坑

- 发完 0x12 没等 BUSY，马上发下一条命令
- 复位后没等 10ms，控制器内部状态还没稳

## 8. 第 6 步：配置面板 `configure_panel()`

### 代码位置

`gdey027t91.cc:563`

### 代码

```cpp
void Gdey027t91::configure_panel()
{
    // 0x01：驱动输出控制
    cmd(Cmd::kDriverOutputControl);
    dat(static_cast<uint8_t>((HEIGHT - 1U) & 0xFF));
    dat(static_cast<uint8_t>(((HEIGHT - 1U) >> 8) & 0x01));
    dat(0x00);

    // 0x18：使用内部温度传感器
    cmd(Cmd::kTempSensor);
    dat(Param::kTempInternal);   // 0x80

    // 0x3C：边框波形
    set_border_waveform(Param::kBorderNormal);   // 0x05

    // 0x11 + 0x44 + 0x45 + 0x4E + 0x4F
    set_full_ram_entry();

    cs_release();
}
```

### 这一步走哪几根线

`configure_panel()` 里的所有 `cmd()` / `dat()` 都走同一组 SPI 线：

| 动作 | 走哪根线 | ESP32 GPIO | 面板 FPC 引脚 |
|---|---|---|---|
| 发命令（0x01/0x18/0x3C/0x11/0x44/0x45/0x4E/0x4F） | MOSI（SDA） | GPIO3 | 14 SDA |
| 命令/数据同步时钟 | SCLK（SCL） | GPIO46 | 13 SCL |
| 选中芯片 | CS# | GPIO9 | 12 CS# |
| 命令时 D/C#=0，数据时 D/C#=1 | D/C# | GPIO10 | 11 D/C# |
| 某些命令后等忙 | BUSY | GPIO12 | 9 BUSY |

所以看代码时：

- `cmd(x)` = 拉低 D/C#，发 1 个字节 `x`，再拉高 CS
- `dat(y)` = 拉高 D/C#，发 1 个字节 `y`
- 每个字节都是通过 GPIO3（SDA）在 GPIO46（SCL）的上升沿逐位送出

---

### 8.1 命令 0x01：Driver Output Control

#### 代码

```cpp
cmd(0x01);
dat((HEIGHT - 1) & 0xFF);        // 263 低字节
dat(((HEIGHT - 1) >> 8) & 0x01); // 263 高字节
dat(0x00);
```

`HEIGHT = 264`，所以 `MUX = 263`，表示 264 行。

#### SSD1680 手册依据

**第 34–35 页 8.1 Driver Output Control (01h)：**

> `MUX[8:0]: Specify number of lines for the driver: MUX[8:0] + 1.`

中文：

> MUX[8:0] 指定驱动行数，实际行数 = MUX + 1。

其他位：

- `GD`：选择第一个输出栅极
- `SM`：栅极扫描顺序
- `TB`：扫描方向（0=从上到下，1=从下到上）

#### 面板手册依据

**第 32 页 14.1：**

```text
• Set gate driver output by Command 0x01
```

#### 常见坑

- MUX 写错，画面会少几行或多几行
- `TB` 写反，画面上下颠倒

---

### 8.2 命令 0x18：Temperature Sensor

#### 代码


### 8.4 命令 0x11：Data Entry Mode

#### SSD1680 手册依据

**第 37 页 8.3 Data Entry Mode Setting (11h)：**

> `AM: Set the direction in which the address counter is updated automatically after data are written to the RAM.`

中文：

> AM 决定写完一个字节后，地址计数器往哪个方向自动更新。

| 位 | 含义 |
|---|---|
| AM=0 | X 方向更新 |
| AM=1 | Y 方向更新 |
| ID[1:0]=00 | X 减、Y 减 |

### 这一步走哪几根线

| 动作 | 走哪根线 | ESP32 GPIO | 面板 FPC 引脚 |
|---|---|---|---|
| 发 0x22/0x20/0x3C/0x24/0x26 等命令 | MOSI（SDA） | GPIO3 | 14 SDA |
| 命令/数据同步时钟 | SCLK（SCL） | GPIO46 | 13 SCL |
| 选中芯片 | CS# | GPIO9 | 12 CS# |
| 命令时 D/C#=0，数据时 D/C#=1 | D/C# | GPIO10 | 11 D/C# |
| 每次触发后等忙 | BUSY | GPIO12 | 9 BUSY |
| 全程不需要拉 RST | RES# 保持高 | GPIO11 | 10 RES# |

**注意：`write_ram_full()` 写 5808 字节时，数据全部从 GPIO3（面板 14 脚 SDA）发出去，时钟是 GPIO46（面板 13 脚 SCL）。**

### 9.5 写上一帧：0x26


`0x26` 写“上一帧/备用 RAM”。

#### 为什么写两遍

局刷和快刷需要比较“当前帧”和“上一帧”。
第一次刷新时两帧内容相同，相当于告诉控制器：

> “上一帧也是这个画面，从这一帧开始建立基线。”

#### 常见坑

- 两帧内容不一致，第一次刷新可能出现残影

### 三种波形总结

| 波形 | 值 | 特点 | 什么时候用 |
|---|---|---|---|

| Partial | 0xFC | 最快、闪烁最少 | 局部更新，依赖基线 |

## 14. 换屏时的最小检查清单

1. **分辨率**：改 `panel.hpp` 的 `WIDTH / HEIGHT`
2. **复位时间**：改 `Panel::RESET_SETTLE_MS`
3. **BUSY 极性**：改 `is_busy()` 里的 `== 1` / `== 0`
4. **SPI 引脚**：改 `config.hpp`
5. **初始化命令**：改 `ssd1680.hpp` 和 `configure_panel()`
6. **波形 LUT**：如果新屏不是 SSD1680 兼容，`0xF7 / 0xD7 / 0xFC` 可能都要换
7. **8 像素对齐**：局刷窗口必须按 X 地址字节对齐

## 15. 一句话总结

```text
上电
→ 配 GPIO / SPI
→ 分配 5808 字节 framebuffer
→ 硬复位（RST 低 10ms、高 10ms）
→ 软复位 0x12（等 BUSY，再等 10ms）
→ 0x01 设 264 行
→ 0x18 用内部温度
→ 0x3C 设边框波形
→ 0x11 设 X/Y 递增
→ 0x44/0x45 设 22 字节 × 264 行
→ 0x4E/0x4F 光标归零
→ 0x22+0xE0 上电 → 0x20
→ 0x24 写当前帧
→ 0x26 写上一帧
→ 0x22+0xF7 全刷 → 0x20 → 等 BUSY
→ 0x22+0x83 断电 → 0x20
```

**手册第 39 页给的是这条主线；每个命令的细节在第 34–38 页；SPI 时序在第 42 页。**

**“RES# 低电平 10ms”不是手册逐字写的，而是代码里的工程保守值；手册明确写的是“复位后 Wait 10ms”。**
